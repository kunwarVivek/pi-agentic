# agentic-pi: delivery plan

Each slice is vertical: it has code, tests and a demo. Slice N+1 starts only after slice N passes `npm run check`.

| Slice | Scope | Exit criteria |
|---|---|---|
| **S0 Scaffold** | Package layout, tsconfig, `node:test`, lint scripts, docs | `npm run check` is green |
| **S1 Pure core** | `manifest` (validate unit.json), `grants` (parse, subset, path match), `policy` PDP, `audit` hash chain, `budget` math, `gates` (schema→rules) | Unit tests cover deny-by-default, narrowing, chain tamper detection |
| **S2 Control store** | `control.db` schema on `node:sqlite`, `ControlStore` (units, tasks, artifacts, approvals, budgets, audit), delegation validation FR3, completion FR4, escalation FR5 | Integration tests on a temp DB with a fake clock |
| **S3 Pi extensions** | `org-policy` (tool_call/tool_result), `org-delegate` tools, `org-context`, `org-trust`, `org-budget` | Extension loads in `pi -e`; hook unit tests with a fake `pi` |
| **S4 Control-plane RPC + dispatcher** | Unix-socket JSON-lines server, peer auth (uid on Linux, token in dev), dispatcher spawning `pi --mode json` per unit | E2E: CEO delegates to sales, sales completes, gate passes, CEO receives the artifact |
| **S5 Lifecycle + scheduler** | TTL, retirement, approval expiry, eval-gated deprecation | Tests with a fake clock |
| **S6 Hardening** | systemd units with a Unix user per unit, bubblewrap/Gondolin for bash, audit anchor export | Linux VM smoke test |
| **S7 Human inbox** | `org approvals` CLI + `/approvals` Pi command; Slack or web later | Approve and deny round trip |

Done: S0 + S1 (17 tests) + S2 control store (10 integration tests, 27 total) + S3 Pi extensions (15 hook tests, 42 total) + S4 Control-plane RPC + dispatcher (10 tests, 52 total) + S5 Lifecycle + scheduler (9 tests, 61 total) + S6 Hardening (14 tests, 75 total). Next: S7 Human inbox.

S6 modules: `src/core/audit.ts` gained the off-host anchor primitives — `buildAnchor(entries,at)→AuditAnchor{count,headSeq,headHash,at,anchorHash}`, `anchorIsIntact(a)` (own-integrity hash, constant-time hex compare), and `verifyAgainstAnchor(entries,anchor)→AnchorCheck` returning `truncated`/`head_mismatch`/`chain_invalid`/`anchor_corrupt` so a full-chain rewrite is detectable against an anchor exported elsewhere. `ControlStore` gained `exportAnchor()` + `verifyAnchor(anchor)`. `src/deploy/systemd.ts` renders a hardened `pi-control.service` and a per-unit `pi-unit@<id>.service` template (user `pi-u-<id>`, `NoNewPrivileges`/`ProtectSystem=strict`/`ReadWritePaths`=workspace only/`RestrictAddressFamilies=AF_UNIX`/empty caps; `SystemCallFilter` blocks `@process` for units without `tool:bash`). `src/deploy/bwrap.ts` turns a unit's path grants into a `bwrap` argv (`--unshare-all --cap-drop ALL`, ro system roots, workspace rw, each `path:rw`/`path:r` grant bound by mode and nothing else). `src/deploy/render.ts` maps a live `control.db` to `{filename:content}` unit files (CLI writes them out, bash flagged from grants, `%i` task specifier). `docs/DEPLOY.md` documents the OS boundary; `scripts/smoke.sh` is the manual Linux/systemd/bwrap S6 gate with helper scripts `seed-smoke-org.ts`/`smoke-e2e.ts`/`smoke-bwrap.ts`/`smoke-anchor.ts` (the three non-root helpers verified end-to-end on macOS).

Known S6 note: `scripts/smoke.sh` needs root + systemd + bubblewrap + Linux, so it is NOT part of `npm test`; it is the manual deployment gate. The live `pi --mode json` worker E2E runs there (the in-repo `smoke-e2e.ts` exercises the full delegate→complete→gate→artifact path in-process without a real worker).

S5 modules: `src/store/control.ts` gained `recordEval(unitId,suite,passed,total)→EvalRow`, `latestEvalRate(unitId)→number|null` (latest run wins), and `sweepLifecycle()→LifecycleTransition[]` (SPEC FR8: `expires_at` past → suspended; idle beyond `retireIdleMs` default 90d, measured from `last_active` falling back to `created_at` → retired; latest eval rate < `min_eval` → deprecated; only active units transition, expiry takes priority). Added `evals` table + `created_at` column on units + `ControlStoreOptions.retireIdleMs`. `src/rpc/scheduler.ts` (`Scheduler.sweep()` = lifecycle → approvals → dispatch in that order; `start()`/`stop()` drive an unref'd interval, overlapping sweeps suppressed). `src/rpc/control-plane.ts` (`startControlPlane(opts)` wires `ControlStore` + `PeerRegistry` + `ControlServer` + `Dispatcher` + `Scheduler`, returns a handle with `stop()`; env-only `main()` guarded by `import.meta.main`; injectable `spawner` + `clock` for tests). A deprecated unit's new delegations are already denied by the existing `from_inactive` status gate in `checkDelegation`.

Known S5 note: `sweepLifecycle` uses the latest single eval run as the pass rate (not a windowed average) — sufficient for FR8; a rolling window can come later if evals get noisy.

S4 modules: `src/rpc/protocol.ts` (JSON-lines framing, `LineDecoder`, `PROTOCOL_VERSION=1`), `src/rpc/auth.ts` (`PeerRegistry`: uid→unit + mode-600 dev tokens, constant-time compare; uid preferred over token), `src/rpc/server.ts` (`ControlServer`: authenticates peer at `hello`, derives unit id from credential never request body, pins task id, ownership-checks complete/escalate/meter, serves snapshots), `src/ext/control-client.ts` (`ControlClient` reads sync from a cached `WorkerSnapshot` so the PDP decides without a round-trip; mutations async; `LocalControlClient` in-process + `BaseControlClient` shared derived reads), `src/ext/socket-client.ts` (`SocketControlClient` over a Unix socket), `src/rpc/dispatcher.ts` (`Dispatcher.tick` polls pending tasks, marks running, spawns worker with ORG_* env; injectable spawner, default launches `pi --mode json`). `unit-config.ts` gained `ORG_CONTROL_SOCKET`/`ORG_UNIT_TOKEN`. `ControlStore` gained `dbPath` getter + `listTasksByStatus`.

Known S4 gaps (resolved in S5): the top-level control-plane binary (`src/rpc/control-plane.ts` `startControlPlane` / `pi-control`) now wires `ControlServer` + `Dispatcher` + `Scheduler`, so `dispatcher.ts`/`defaultSpawner` are reached in production. Still no live `pi --mode json` E2E (spawner is injected/faked in tests)—deferred to S6 Linux VM smoke test.
